# QElectroTech 作図の勘所

実案件（制御盤の改造）で踏んだ落とし穴をまとめたもの。
QET は日本語の情報がほとんど無く、**症状から原因にたどり着くのに時間がかかる**。

## まず確認すること

作図の相談を受けたら、最初にこの3つを確認する。

1. **起動方法** — スタートメニュー（`Lancer QET.bat`）から起動しているか
2. **どのコレクションの部品を使っているか** — `91_en_60617` を作図に使っていないか
3. **ユーザーコレクションの場所** — `%APPDATA%\qelectrotech\QElectroTech\elements\`

## どの記号を使うか

このリポジトリの記号を使う。**番号を思い出せなくても形から引ける。**

| | |
|---|---|
| `docs/カタログ.md` | 全部の姿を節ごとに並べたもの |
| `docs/チートシート.svg` | よく使うものだけの A4 1枚（印刷用）。決めごとも載っている |
| `docs/採録状況.md` | 図記号番号と名称の一覧 |

よく使うものの見当。**接点は 07-02、限時接点（タイマ）は 07-05、押しボタンなど
手動操作は 07-07、リミットスイッチは 07-08、電磁接触器や遮断器は 07-13、
コイルは 07-15、ヒューズは 07-21。**

**`07-A` は使わない。**規格の附属書Aに載っている既に削除された図記号で、
古い図面を読むための参考として置いてある。新しい図面に使うと誤りになる。

## 症状 → 原因の対応表

| 症状 | 原因 | 対処 |
|---|---|---|
| **部品が1つも出てこない** | `bin\qelectrotech.exe` を直接起動した | スタートメニューから起動する（後述） |
| **UIがフランス語** | 同上、または言語未設定 | 同上。QETの既定言語はフランス語 |
| **線が引けない／つながらない** | `91_en_60617` の部品を使っている | 作図用の部品を使う。標準の規格記号集は**63%が端子を持たない** |
| **分岐が描けない** | ジャンクション部品を探している | **存在しない。** 同じ端子に2本目の導体をつなぐ |
| **接点のラベルが意図と違う文字になる** | master/slave のラベル自動同期 | `text_from="UserText"` にする（後述） |
| **図面が読み込めない／XMLエラー** | `text` 属性に生の `"` を入れた | タグは実体参照で書く（後述） |
| **記号の形がおかしい** | 座標だけ見て作った | **必ず画像に描き出して目視する** |

## 起動

QET は**シンボル集・言語ファイル・図枠の場所をコマンドライン引数で受け取る**。
exe を直接起動すると `bin\` の下を探しに行って失敗し、UIがフランス語になり**部品が0個**になる。

```
qelectrotech.exe --common-elements-dir=elements/ --common-tbt-dir=titleblocks/ --lang-dir=lang/
```

インストーラが作るスタートメニューのショートカットはこれを実行している。

**確認方法** — 起動ログを見る。

```
%APPDATA%\qelectrotech\QElectroTech\<日付>.log
```

```
Count All Elements in collections = 8597 Elements   ← 正常
Count All Elements in collections = 0 Elements      ← 起動方法が間違っている
```

言語はレジストリ `HKEY_CURRENT_USER\Software\qelectrotech\QElectroTech` の `lang`（文字列）。

## コレクション

| 種別 | 場所 | 用途 |
|---|---|---|
| 標準 | `<インストール先>\elements\` | 8,000種超。ただし後述の注意 |
| ユーザー | `%APPDATA%\qelectrotech\QElectroTech\elements\` | 自作部品。**クラウド同期の対象外** |

### `91_en_60617` は作図に使わない

IEC 60617 の**規格リファレンス集**であって作図用ではない。**約63%の部品が端子を持たない**ため、
置いても導体がつながらない。作図には端子を持つ部品を使うか、自作する。

### 部品パネルは表示名しか出さない

端子類はどれも "Terminal block" と表示されて区別できない。形（中心の丸から出る線の本数と向き）
で見分けるか、日本語名を付けた自作コピーをユーザーコレクションに置く。

### ライセンス

`ELEMENTS.LICENSE` に明記されている。

- **回路図の中で使う・改変する・組み込む** → 無条件。図面のライセンスも自由
- **回路図の外でコレクションの全部または一部を再配布する（改変の有無を問わず）** → **CC-BY** の条件に従う

シンボル集として配布する場合は後者。`Author: The QElectroTech team` の帰属表示を落とさないこと。
**帰属を避けたいなら、上流から派生させず自分で描き起こす。**

## 作図の原則

**導体は端子と端子の間にしか引けない。** 空中に線だけを引くことはできない。

これが最初の壁になる。母線は「横線を引いてラングをぶら下げる」のではなく、
**部品を並べて端子同士をつなぐと結果的に母線に見える**、という順序で作る。

- ラングの部品を横一列に並べ、**上端の端子のY座標を揃える**
- 隣どうしの端子を導体でつなぐ → 横方向の区間が一直線に並ぶ
- 分岐は**同じ端子に2本目の導体**をつなぐ

## ラベルと相互参照（最大の落とし穴）

部品定義は `link_type` を持つ。

| link_type | 該当 |
|---|---|
| `master` | コイル・操作器 |
| `slave` | その接点 |

**スレーブの `label` は、リンク先マスタから QET が自動同期する。**

配置側の文字が `text_from="ElementInfo"` ＋ `<info_name>label</info_name>` だと、
この同期された label を表示する。つまり**接点に独自の文字を付けても、コイルの文字で上書きされる**。

### 接点に独自表示をしたい場合

`text_from="UserText"` にして `<info_name>` を**書かない**。固定文字として表示され、マスタから独立する。
相互参照は `<links_uuids>` 側にあるので影響しない。

```xml
<dynamic_elmt_text x="..." y="..." rotation="0" frame="false"
                   font="..." uuid="{...}" text_width="-1"
                   Halignment="AlignLeft" Valignment="AlignTop"
                   keep_visual_rotation="true" text_from="UserText">
    <text>t1</text>
</dynamic_elmt_text>
```

> **`keep_visual_rotation` は必ず `true`。** 部品を倒したときに文字まで倒れるのを防ぐ。
> QET は `true` のとき文字の回転を「基準 − 親の回転」に置いて親の回転を打ち消す
> （`dynamicelementtextitem.cpp` の `parentElementRotationChanged`）。
> 属性を省いたときの既定も `true` なので、**明示的に `false` と書いたときだけ倒れる。**

> **日本の慣習**：コイルを大文字（T1・M1・R1）、その接点を小文字（t1・m1・r1）にすると、
> 印刷したときに一目で区別できる。既設盤の図面でも広く使われている表記。

### フォリオ参照（ページをまたぐ導体）

`link_type` は **`next_report`（次ページへ）／`previous_report`（前ページより）**。

**2つの札を明示的にリンクする。** 右クリック → **「リンクする要素」** →
相手の札をクリック。解除は **「要素のリンクを解除」**。

| 思い込み | 実際 |
|---|---|
| 導体の線番が一致すれば QET が結ぶ | **結ばない。線番は関係ない** |
| 参照先はファイルに保存されない | **`<link_uuid>` として保存される**。結果も `elementInformation name="label"` に入る |

**リンクしていない札は `/` と表示される。**空欄ではないので、
`/` が出ていたら「リンクし忘れ」とすぐ分かる。

表示の書式は プロジェクトの属性 の**「フォリオ参照のラベル」**
（`.qet` では `<report label="%f-%l%c" />`）。`%f`=フォリオ `%l`=行 `%c`=列。

> **同梱の作例が答えを持っている。** `C:\Program Files\QElectroTech\examples\`
> の `Projet_vierge.qet` や `iso_sfc_example.qet` に、リンク済み（`label` に `2-A3`）と
> 未リンク（`label` に `/`）が両方入っている。**仕様を推測する前にここを見る。**

### 相互参照の表示

プロジェクトの `<xrefs>` で制御する。

```xml
<xref type="coil" displayhas="cross" slave_label="(%f-%l%c)" master_label="%f-%l%c" snapto="bottom" />
```

`%f`=フォリオ `%l`=行 `%c`=列。接点の脇にコイルの位置が `(2-B8)`、コイルの下に接点の位置一覧が出る。
**ラベル（何の接点か）と位置（相手はどこか）は別物なので、両方そろえて初めて紙面で追える。**

## 図面XMLを直接書くときの注意

`<diagram>` は `<elements>` `<conductors>` のほかに次を持てる。

### 矩形（盤の境界など）

```xml
<shapes>
    <shape z="0" x1="150" y1="180" x2="470" y2="1180" rx="0" ry="0"
           closed="0" type="Rectangle" is_movable="1">
        <pen color="#000000" widthF="0.6" style="DashLine"/>
        <brush color="#000000" style="NoBrush"/>
    </shape>
</shapes>
```

### 独立テキスト

```xml
<inputs>
    <input x="60" y="30" rotation="0" font="Sans Serif,10,-1,5,50,0,0,0,0,0" text="凡例 ..."/>
</inputs>
```

> **`text` 属性の中身は Qt のリッチテキスト。** タグを書くなら `&lt;b&gt;` のように実体参照にする。
> **生の `"` を入れるとXML属性が壊れて図面が読み込めなくなる。**

## 検証

作図したら機械的に確認する。`.qet` は XML なので自作スクリプトで検査できる。

| 観点 | 見るもの |
|---|---|
| 重なり | 部品の外形（`.elmt` の width/height/hotspot）同士の交差 |
| 図枠はみ出し | `cols*colsize` × `rows*rowsize` の外に出ていないか |
| 端子未指定 | `<conductor>` に `element1/terminal1/element2/terminal2` が揃っているか |
| 相互参照 | `<link_uuid>` の数 |
| 線番 | `<conductor num="...">` の一覧。**欠番があれば転記ミスを疑う** |

**記号を作ったら必ず画像に描き出して目視する。** 座標を読むだけでは形の誤りに気づけない。
実例：ブザーのリードを弧の側から出していた／直流モーターの記号が実線1本だけだった（正しくは実線＋破線）／
横向きにしたとき文字まで倒してしまった（**文字・識別記号は倒しても正立のまま**が正しい）。

## 帳票

| 欲しいもの | QET の対応 |
|---|---|
| 部品表 | 標準機能で集計・CSVエクスポート |
| 線名リスト | エクスポートあり |
| 端子台表 | 端子台プラグインあり |
| 内部プロジェクトDB | エクスポートあり。任意の帳票の材料にできる |
| **配線表（from-to）** | **標準エクスポートなし。** `.qet` の XML から自分で抽出する |

from-to の抽出は `<conductor>` の `element1/terminal1 → element2/terminal2` を辿ればよい。
`<element>` の `uuid` と `elementInformation name="label"` で機器名を引く。

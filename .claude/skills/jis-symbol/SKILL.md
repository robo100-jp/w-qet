# JIS C 0617 の図記号を描き起こす

実機（QElectroTech 0.100.0 / Windows）で確かめて分かったことをまとめたもの。
**問題が出るたびにここを直す。**

作図（`.qet` を描く）側の勘所は別のスキル `qelectrotech` にある。
**XML の構造そのもの**（タグ・属性・座標の意味・公式仕様書とのちがい）は
[docs/QETのXML.md](../../../docs/QETのXML.md)。

---

## 一つ描くときの手順

```bash
py -3 tools/status.py --next 10        # 次の番号と規格票のページ
```

1. `py -3 tools/stdpage.py <ページ>` でそのページを測る。**説明欄も読む**
2. `tools/elmtgen.py` を使う生成スクリプトを**スクラッチパッドに**書いて `.elmt` を吐く
   置き場所は `elements/JIS_C_0617/<節>/<番号>.elmt`。**節のフォルダ名もASCII**
3. `py -3 tools/render_elmt.py <番号>` で**目視**
4. `py -3 tools/check_elmt.py` で**機械の点検**。目視で出ない不備を拾う
5. `py -3 tools/compare_page.py <番号>` で**規格票と並べる**。寸法が数値で出る
6. `py -3 tools/status.py` と `py -3 tools/sympage.py` → `git commit` → `git push`

**3・4・5 は役割が違う。全部かける。**

| | 見るもの |
|---|---|
| `render_elmt.py` | 形が規格どおりか（目で見る） |
| `check_elmt.py` | 外形・端子・属性が壊れていないか（絵に出ない） |
| `compare_page.py` | 規格票と寸法が合っているか（目分量では出ない） |

**記号を足したり直したら `sympage.py` も叩く。**`docs/sym/` の
1個1枚の頁・目次・注釈のページ・SVG が `elements/` から作り直される。
`status.py` が採録の「数」を数え直すのと同じで、**一覧を手で書かない。**

### `docs/sym/*.html` には**人が書き込む欄**がある

**依頼者がこの頁を直接書き換える。**印で挟んだところは作り直しても消えない
（`sympage.py` が書き出す前に既存の頁から読み戻す）。

```html
<!--hand:memo-->  ここに書く  <!--/hand:memo-->
```

| 印 | 何を書く欄か |
|---|---|
| `memo` | 覚え書き。使ってみて分かったこと、選ぶときの目安 |
| `cad` | **CAD用シンボルにするか。**「する。」「しない。」で書き始める |
| `combine` | 組合せ。他と組んで別の記号にするときのこと |

`cad` と `combine` は「この図記号から何を作るか」で**1つの節にまとめてある**
（同じ種類の判断なので離さない）。

- **印を消さない。** 消えると読み戻せない
- **`docs/sym/*.html` を機械的に消して作り直さない。** `sympage.py` は
  消す前に読むが、自分で `rm` してから叩くと**人の書き込みごと消える**
- **判断の置き場は頁だけ。** Claude が規格票から判断して書くことも、
  人が書くこともあるが、tsv などに分けると二重管理になる。
  `paths.cad_policy()` が `docs/sym/*.html` を走査して数える
- **`install.py` は「しない」を QET に入れない。** 図と頁は作るが、
  部品パネルには並べない

### 「しない」と決めてあるもの

| | なぜ |
|---|---|
| **旧図記号（附属書A。`07-A*` `08-A*`）** | 新しい図面には使わない。`sympage.py` が既定で「しない」を焼く |
| **使用例** | 装置ではなく**使い方**を示す図。07-A11（多段スイッチの例）・07-A12-02/03（構造図と接続表）がこれ |

**図（SVG）と頁は、しないものにも作る。**古い図面を読むときに姿が要るし、
一覧から黙って落とすと描き忘れたのか決めて外したのか分からなくなる。

> **図（SVG）と頁は、CAD用シンボルにしないものにも作る。**
> 一覧から黙って落とすと、描き忘れたのか決めて外したのかが分からなくなる。

よく使うものを載せた `docs/チートシート.svg`（印刷用 A4 1枚）は `cheatsheet.py`。

## ファイル名の区切り —— **`__` の後ろは規格に無いもの**

| 区切り | 意味 | 例 |
|---|---|---|
| `-` | **図記号番号そのもの** | `07-02-01` |
| `_` | **規格の中でつなぐ。**番号どうしの組合せ | `07-07-02_07-07-07` |
| `__` | **規格に無いものを足す** | `08-10-01__green`（色）・`07-11-04__3`（段数） |

**`__` から後ろを切れば、前は必ず規格に由来する名前になる。**
`check_elmt.py` はそうやって組合せかどうかを見分ける。

```python
stem = base[:-5].split("__")[0]     # 規格に由来する部分だけ
if "_" in stem:                     # 番号どうしをつないだ＝組合せ
```

- **`+` を使わない。** HTTP サーバでエスケープが要る（`%2B`）。
  `_` は URL の予約文字ではないのでそのまま置ける
- **ファイル名は ASCII。** 日本語だと QET が記号名をファイル名に化けさせる

## QET で表示が壊れる条件（**知らないと必ず踏む**）

| やってしまうこと | QET でどうなるか |
|---|---|
| **ファイル名に日本語** | 記号名が `<name lang="ja">` ではなく**ファイル名（拡張子つき）に化ける** |
| **フォルダ名に日本語** | `qet_directory` が読めず、部品パネルで**フォルダ名が空欄**になる |
| **外形 10×10** | プレビューを作れない。ログに `QPainter::begin ... engine == 0` |
| **文字が外形からはみ出す** | 動かしたとき**画面にゴミが残る**（再描画は外形の矩形だけ） |
| **破線の刻みを指定する** | できない。`line-style:dashed` は Qt のペンそのまま（**4:2**＝刻み 0.6M）。規格票は刻み 1.0M だが、同梱コレクションも 918個が同じ指定で済ませている |
| **外形が10の倍数でない** | 同梱8597個すべてが10の倍数。実装側の要求と見てよい |

**どれも `.elmt` を絵にしただけでは分からない。** `check_elmt.py` が全部弾く。

## 文字

**`1em = ポイント数 × 96/72`。** Qt が pt を画素に直す比。

### 大きさは **9pt**

規格票の図の中の文字は、どのページでも**字面 0.90〜0.93M**（実測。第7部全ページ）。
Liberation Sans（≒Arial）で測ると **9pt が 0.86M** で最も近い。10pt は 0.96M。

**下付き**（`U` に対する `rsd` など）は 6pt。規格票の小さいほうの実測 0.60M と一致する。

> **`>` `<` が本文より小さく見えるのは正しい。** 字そのものが小さい（9pt で 0.58M）。
> 規格票も同じ比で、フォントを変えているわけではない。

**字面は表で見積もらず実際に描いて測る。** 送り幅の表は空白や記号を取りこぼすし、
上下の高さは em の割合で当てるしかない。`check_elmt.py` は Arial で実測している。

> かつて 6〜8pt が混ざっていて、小さいものは 0.60M しかなかった。
> 大きさをそろえたら **07-12-06 は行が重なった** —— 規格票を測り直すと箱が 2M 高く、
> 行間も 1.27M（こちらは 0.95M）あった。**文字が小さいまま辻褄が合っていただけ。**

**大きさを変えたら位置も直す。** 字送りが変わるので x をそのままにすると寄る。
同じベースラインで隣り合う文字は、見た目の中心を保ってひとつづきに並べ直す。

### 置くときは**字面の中心**で合わせる

規格票から読めるのは「字面がどこからどこまでか」であって、ベースラインではない。
`check_elmt.text_box(s, pt, italic)` が字面の (左, 上, 右, 下) を実測で返すので、
そこから逆算してベースラインを決める。生成スクリプトに毎回これを書く。

```python
def ctext(s, cx, cy, pt=9, italic=False):
    b = CE.text_box(s, pt, italic)
    return G.text(cx - (b[0] + b[2]) / 2.0, cy - (b[1] + b[3]) / 2.0, s, pt, italic)
```

### **pt ではなく字面で合わせる**

`*` は字形そのものが小さい。**9pt では字面 0.36M にしかならず、規格票の 0.62M に
届かない。14pt で 0.61M。**「記号の中の文字は 4〜10pt」という当ては、
字面が em に対してどれだけ大きいかで変わる。**規格票の字面を測って合わせる。**

| | 規格票の字面 | 合う大きさ |
|---|---|---|
| 英大文字（`V` `I` `Wh`） | 0.90〜0.93M | **9pt** |
| 下付き（`rsd` `max`） | 0.60M | **6pt**（または同じ大きさでベースラインを下げる） |
| 肩の数字（`10³` の `3`） | 0.64M | **7pt** |
| `*` | 0.62M | **14pt** |

**下付きと肩の数字を同じ大きさだと決め込まない。**測ると 0.60M と 0.64M で違い、
6pt と 7pt に分かれた。**毎回そのページの字面を測る。**

> かつて `1em = 0.78 × pt` と誤っていた。**QET では1.7倍**になり、
> 文字が外形からはみ出して画面にゴミが残った。
> **描き出し側と生成側が同じ係数で間違えていたので、目視でも検査でも通ってしまった。**
> 数式を疑うときは**同梱コレクションの統計と突き合わせる。**

### `<text>` と `<dynamic_text>` の使い分け

| | 用途 | 座標の意味 | 回すと |
|---|---|---|---|
| `<text>` | 記号の一部（`Θ` `V` `I >`） | **ベースラインの左端** | 一緒に倒れる |
| `<dynamic_text>` | ラベル欄、編集させたい値 | **外接矩形の左上** | `keep_visual_rotation` 次第 |

置き換えるときは **`y_上端 = y_ベースライン − 0.905 × em`**。

- **ラベル（`text_from="ElementInfo"`）は `keep_visual_rotation="true"`。** 倒しても正立
- **記号の中の文字は倒れてよい。** 決めてある（`docs/寸法基準.md`）
- **規格票が「例」として示している値**（`5…10 A` など）は
  `text_from="UserText"` にして図面上で書き換え・削除できるようにする。
  **`I >` のような定義そのものの記号は静的な `<text>` のまま**

### link_type —— 接点は自分がスレーブだと宣言する

**`.elmt` が持つのは役割だけ。**どのコイルとどの接点が対かは `.qet` 側にある。
だが**役割を書いていないと相互参照そのものが張れない。**

| | 例 | link_type |
|---|---|---|
| ラベルをマスタから取る**接点** | a接点、限時接点 | **`slave`** |
| **接点を別の場所に描く側** | 継電器コイル | **`master`** |
| それ自体が機器（**接点を内蔵**して1つで完結） | 押しボタン、リミットスイッチ、温度スイッチ | `simple` |
| 限定図記号（端子を持たない） | 接点機能 | `simple` |

**「接点」と名が付いていても機器なら `slave` ではない。**
逆に、純粋な接点を `simple` のままにするとラベルが同期されない（実際にやった）。

## 矢羽根は**開いた V 字**……とは限らない

**ページごとに違う。1つ測って全部に当てない。**行走査で見分けられる。

| 見え方 | 走査での見分け | 何に使われているか |
|---|---|---|
| **開いた V 字** | 底のあたりで**離れた2本**の短い区間になる | エネルギーの向き（08-04 の積算計・08-02-03） |
| **塗り三角** | どの行も**底辺の x から途切れず**先端へ短くなる | 計器の針（08-02-08・08-02-12）、プリセット／リセットの矢（08-05-03・08-05-04） |

- 開いた V 字は `end2="simple"`。大きさは実測 0.7M ＝ `len2=3.0`
- 塗り三角は **`<polygon>` で描く。`end2="triangle"` は使えない**——
  QET の三角は長さと半幅が等しく、規格票の 0.78M×0.50M（幅は長さの 0.64）に
  ならない。底辺の中央と先端を指定して自分で3点を置く

## 同じ図記号でも大きさが違う

**規格票は場所によって同じものを違う大きさで描いている。**揃っていない。

| | 単独のページ | 組み込まれた図 |
|---|---|---|
| 断路遮断機能の星（07-01-10） | 1.26×1.04M | 07-13-17 の中では **1.0M** |

**そのページの実測に従う。**ただし限定図記号のように他の記号に組み込むものは、
**組み込んだときに揃うほう**を採る（07-01-10 は 1.0M にしてある）。

> **「大きさが違う」と決める前に倍尺を疑う。** 08-10-02 のランプが 08-10-01 の
> 倍あると書いていたが、**あれは 200 % のページだった**。実寸に直すとぴたり同じ。
> 上の「測るときの落とし穴」を見ること。

## 弧の角度

| | 0度の向き | 正の角度 |
|---|---|---|
| QET / Qt | 3時方向 | **反時計回り** |
| Pillow | 3時方向 | **時計回り** |

`.elmt` には **QET の流儀**で書く。`render_elmt.py` が反転して描く。

## 規格票を測る

規格票は**リポジトリの外**（`%USERPROFILE%\規格\`）。`.gitignore` で二重に弾いている。
**図版も PDF もリポジトリに入れない。**在りかは `paths.standard()` が解決するので、
パスをソースに書かない。

```bash
py -3 tools/stdpage.py 78            # 格子と、図の墨の成分を M で並べる
py -3 tools/stdpage.py 78 --rows     # 行走査（斜線の折れ点を見る）
py -3 tools/stdpage.py 78 --png      # 図だけ切り出す（出力はリポジトリ外）
```

**使い捨ての道具を書く前に `stdpage.py` を import する。**
`Page(78)` が帯・格子・墨の成分を持っているので、たいていの測定はそれで足りる。

### 測るときの落とし穴

**縮尺・格子・帯・ドット・倍尺は `stdpage.py` が中で処理している。**
自分で書き直すときに踏み直さないために残す（同じ穴に2回落ちた）。
**走査の刻みだけは呼ぶ側の責任。**

- **縦横で縮尺が違う。** 表のセルに入っているせいで列と行の間隔が最大6%ずれる。
  **必ず別々に測る**
- **1目を「間隔の中央値」で決めてはいけない。** ドットは図に隠れて飛ぶし、
  図の小さな部品や表の切れ端がドットに混じる。中央値も最頻値もそれに引きずられ、
  あるページで **1M が半分**に、別のページで **7% 大きく**出た。
  **周期そのものを合わせる**（Σ exp(2πi x/p) の大きさが最大になる p を探す）。
  ドットが欠けても余計な点が混ざっても効く
- **図の帯は「横罫線と横罫線のあいだ」。**最初の罫線で切ると、表の見出し行の
  罫線が図より上にあるので図ごと落ちる。罫線を連結成分として拾おうとしても、
  表の枠は全部つながっているので拾えない。**行ごとに暗い画素の連続の長さを見る**
- **帯をドットの数だけで選ばない。** 説明表の句読点が図のドットより多いページがあり、
  表のほうを図と取り違えた。**格子らしさ（周期のそろい具合）で重みを付ける**
- **ドットは「孤立しているか」で判定しない。** 図に寄ったドットは孤立判定に落ち、
  そのまま墨に数えられて図の外形が上下左右に最大1Mずつ膨らむ。
  **大きさだけで外す**
- **倍尺のページがある。** 小さい図記号は2倍に拡大して刷ってあり、
  図記号欄に **`200 %`** と付く（規格票の「概要」に書いてある）。
  **格子のドットは拡大されない**ので、図だけがドット2目で1M になる。
  気づかずに測ると**倍の大きさの記号を作る**。`200 %` の文字そのものも
  墨に数えられて外接矩形が伸びる。`stdpage.Page.scale` が両方処理する。
  説明欄にも「再設定比は 130 %」のような数字＋% が出るので、
  **図の帯の中にあるものだけ**を倍率と見ること
- **走査の刻みは 0.2M 以下。**これより粗いと線を踏み外す。第8部だけで4回落とした。

  | 落としたもの | 何に見えたか |
  |---|---|
  | 音響信号装置の弦（08-10-06） | 弦の無い開いたドーム |
  | サイレンの底辺（08-10-09） | 閉じていない三角形 |
  | 表示器の白帯2本（08-10-03） | 白い円に黒帯1本（実際は**黒い円に白帯2本**） |
  | 事象数計数機能の破線（08-05-01） | 破線が丸ごと無い |

  **形が変わって見えるのに気づけない**のがたちが悪い。`stdpage.Page.rows(0.2)`。
  節目（弦・底辺・軸）の座標は必ず踏む
- **測定メモを鵜呑みにしない。** 描く前にそのページをもう一度走査する
- **限定図記号の中をリード線が通らないことがある。**
  行走査で中心の x に暗い画素が無いかを見れば分かる
- **規格票にリード線が無い図記号がある。** 外形の縁に端子を足し、
  足したことを `<informations>` に必ず書く

## 寸法・端子

詳細は `docs/寸法基準.md`。要点だけ。

- グリッド **10**。これは規格の作図モジュール **M** と一致する（実測で確認）
- 端子間は**縦置きの機器 60**（`y = ±30`）／**端子・ジャンクション 30**（`y = ±15`）
- `hotspot` は既定で外形の中央。左右非対称なら `hx` をずらす
- 端子には **`uuid` `name` `type="Generic"` `orientation`** が必須
- **`<terminal>` の並び順を後から変えない。** 出現順に id が振られ、
  既に作った `.qet` の導体のつながり先がずれる
- **可動接片の角度は規格票がページごとに揺れている。** 揃えると決めてある。
  `docs/寸法基準.md` の表に従い、ページの値をそのまま採らない

## 規格票が「例」でしか示していないもの

規格票は1つの例しか載せていないが、実務では**数が変わる**ものがある
（多段スイッチの位置の数、継電器の動作値など）。

| 変わるもの | 直し方 |
|---|---|
| **値・文字** | `<dynamic_text text_from="UserText">` にして図面上で書き換えられるようにする |
| **形**（段数・極数） | **別ファイルとして起こす。** 編集では変えられない |

### 規格に番号の無い組合せ

規格は**操作子の限定図記号と接点を組み合わせる**建て付けなのに、実務で必ず出る
組合せに番号が無いことがある（押しボタンの b接点）。**組んでよい。番号は騙らない。**

| | 決め |
|---|---|
| 置き場所 | **組合せ元と同じ節**。別フォルダに隔離しない（探すとき節を開く） |
| ファイル名 | `07-07-02_07-07-07.elmt` —— 番号を **`_`（アンダースコア1つ）**でつなぐ |
| informations | `JIS C 0617 の組合せ 07-07-02 ＋ 07-07-07`。**番号の行は書かない** |
| 作り方 | `elmtgen.write(..., num=None, combo=("07-07-02", "07-07-07"))` |
| 座標 | **組合せ元からそのまま採る** |

`check_elmt.py` が照合する。番号の行を書くと `status.py` が採録として数えてしまう。

---

形を増やすときは、**規格票の例をその規則で再現できるか**を必ず確かめる。
07-11-06（多段スイッチの位置図）は「一番外の光線を ±40 度に置いて等間隔に割る」
という規則にしたら、4位置が規格票の実測（±19°・±40°）と一致した。
**一致しない規則なら読み違えている。**

## 描いたあとで規格票と突き合わせる

```bash
py -3 tools/compare_page.py 07-02-01 07-02-03    # 並べた画像（出力はリポジトリ外）
py -3 tools/compare_page.py --num --all          # 数値だけ全件。数分かかる
```

一度描いたものを並べ直すと誤りが出る。ただし**数値がちがう＝誤り、ではない。**
仕分けてから直す。**順番を間違えると正しい記号を壊す。**

| 仕分け | 見分け方 |
|---|---|
| **測り方の誤り** | **まずこれを疑う。** 上の「測るときの落とし穴」 |
| **決めごとどおり** | 引出し線の長さ（端子間 60）・可動接片の角度。`docs/寸法基準.md` |
| **規格票に図が複数** | 向きちがいを2つ並べているページがある |
| **規格票に格子が無い** | 07-16-02〜07-16-10 の9枚。`—` と出る。目視だけ |
| **本当の誤り** | 上のどれでもないとき |

> 「要修正」と判断した2件が、格子の測り直しで**どちらも正しかった**。
> 道具を疑う前に記号を疑って、直しかけた。

**規格票の説明欄を読む。図だけ見ていると落としに気づけない。**

| 欄 | 何が分かるか | 落とした実例 |
|---|---|---|
| **補足事項** | 図に描かれている部品の一覧 | 07-13-12「戻り止め付き手動引外し装置」を描いていなかった |
| **形状分類** | 「点」「線」「長方形」など、図を構成する形 | 07-15-16「点」＝黒丸2つを落としていた |
| **注釈** | 他の図記号と共通の制約・**符号の決め** | 位置図に文字を足してよい（A00251）。ランプの色は RD/YE/GN/BU/WH（A00174） |

> **制約の出どころを取り違えていた。**「07-11-05/06 は最大4位置（A00060）」と書いていたが、A00060 は支点の小円の話。
> **4位置の制限は 07-11-05 の名称そのもの**（「多段スイッチ（最大 4 位置）」）から来ている。07-11-06 に上限は無い。
> **制限事項・注釈・名称のどこから来た制約かを、書くときに確かめる。**

> **注釈は番号（`A00174`）しか書いていない。**中身は巻末の注釈の節にある。
> 番号を PDF 全体から引き直すこと。ランプの色の符号を自分で決めて
> `G`・`R`・`Y`・`W` と書いてしまい、あとで規格の符号に直した。

```bash
py -3 -c "import sys;sys.path.insert(0,'tools');sys.stdout.reconfigure(encoding='utf-8');import paths,pypdfium2 as p;print(p.PdfDocument(paths.standard(8))[57].get_textpage().get_text_range())"
```

**説明欄の照合は節ごとではなく部ごとに一度、全件でかける。**書きながら1枚ずつ
読むと、他の記号と共通の注釈（`A00174` のような）を落とす。第7部・第8部とも、
描き終えてから全件を通し読みして拾った。

| 欄 | 照合のしかた | 出てきたもの |
|---|---|---|
| 形状分類 | 図形の種類（`<line>` `<ellipse>` …）と機械的に突き合わせる | 第7部22件・第8部4件が引っかかり、**全部空振り**。折れ線を `<polygon>` で描くなど、同じ形を別のプリミティブで描いているだけ |
| 補足事項 | 「〜しなければならない」「〜だけに使用する」を探す | 第7部2件・第8部23件が本物 |
| 注釈 | **番号（`A00174`）しか書いていない。**巻末の注釈の節を引く | 符号の決め・組合せ方・形が変わる規則 |

**フォントは合わない。** 規格票は変数をセリフ斜体で組んでいる（`U` `I` `P`）。
こちらは Liberation Sans。**形は合わせるが書体は合わせない**と決めてある。

## 新しい部を買ったときの手順

**ここに書いてあるとおりにやれば、第7部・第8部で踏んだ穴を踏まずに済む。**
道具はもう部を受け取る（`--part`）。

### 1. PDF を置く

`%USERPROFILE%\規格\jis_c_00617_<3桁の部>_*.pdf`。`paths.standard(N)` が拾う。
**パスをソースに書かない。リポジトリにも入れない**（`.gitignore` で二重に弾いてある）。

### 2. 索引を作る —— **手で作らない**

```bash
py -3 tools/mkindex.py --part 6 --write     # docs/規格データ/第6部索引.tsv
py -3 tools/mkindex.py --part 6             # 突き合わせ（差があれば終了コード1）
```

> **手で作って 19個を丸ごと落とした。** 第7部の索引が附属書A の途中で切れていて、
> `status.py` が **161/161 と嘘の採録率**を出していた。実際は 161/180。
> 分母を手で作ると、**足りないことに気づく手立てが無くなる。**
> `mkindex.py` は「番号のすぐ後ろに識別番号（S00227）が続くページ」だけを拾う。
> 「図記号番号」という語だけで拾うと、巻頭の表1（項目名の説明）を誤って拾う。

### 3. 注釈を読んで tsv に落とす

**規格票の各図記号には「注釈」（`A00174` のような番号）が付いている。
中身は巻末の注釈の節にあり、番号しか書いていないので引かないと読めない。**

```bash
py -3 -c "import sys;sys.path.insert(0,'tools');sys.stdout.reconfigure(encoding='utf-8');import paths,re,pypdfium2 as p;d=p.PdfDocument(paths.standard(6));print(''.join(re.sub(r'\s+',' ',d[i].get_textpage().get_text_range()) for i in range(len(d)) if '図記号番号' not in d[i].get_textpage().get_text_range()))"
```

2つ作る。

| ファイル | 中身 | 作り方 |
|---|---|---|
| `docs/規格データ/第<N>部注釈.tsv` | `番号 ⇥ 表題 ⇥ 要点` | **要点は自分の言葉で書く**（本文を写さない） |
| `docs/規格データ/第<N>部注釈_適用.tsv` | `番号 ⇥ 適用される図記号` | 各図記号ページの「注釈」欄から機械で抜く |

> **注釈を後回しにしない。** 第8部では図を描き終えてから読み、
> ランプの色の符号を自分で決めていたのが規格に定めがあると分かって直した（A00174）。
> **第7部は注釈32種のうち A00060 が50個・A00061 が53個に効いていた。**

### 4. 節のフォルダを作る

`elements/JIS_C_0617/<節>/` に `qet_directory`。**フォルダ名は ASCII**。
**旧図記号（附属書A）は `<部>-A` にまとめ、「参考・使わない」と書く。**

### 5. 描く

```bash
py -3 tools/status.py --part 6 --next 5
```

**節ごとにまとめて描くほうが速い。**同じ節の記号は枠が同じで中身だけ違うことが多い
（第8部は 67個中 50個以上が「枠＋中の文字」だった）。1枚ずつ測るより、
ページを並べた画像を1枚作って**中の文字だけ先に読む**ほうが手数が少ない。

### 6. 突き合わせる

```bash
py -3 tools/check_elmt.py
py -3 tools/compare_page.py --num --all --part 6
```

### 7. 説明欄を**全件**通し読みする

**節ごとに読まない。部を描き終えてから一度に、全件でかける。**
書きながら1枚ずつ読むと、他の記号と共通の注釈を落とす。

### 8. 作り直してコミット

```bash
py -3 tools/status.py --part 6
py -3 tools/sympage.py        # docs/sym/（1個1枚の頁＋目次＋注釈）
```

`cheatsheet.py` は A4 に空きが無いので、載せるなら何かを落とす。

## 心構え

- **症状を1つの原因で説明しようとしない。** 「フォルダ名が空」と
  「記号名がファイル名になる」は別々の原因だった。片方を直しても片方は残る
- **仮説を「外れ」と早々に切らない。** 依頼者の指摘が正解だったのに一度否定した
- **「入れておきました」と言わない。** 実ディスクに届いたか確かめられない

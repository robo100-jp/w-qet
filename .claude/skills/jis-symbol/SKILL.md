# JIS C 0617 の図記号を描き起こす

実機（QElectroTech 0.100.0 / Windows）で確かめて分かったことをまとめたもの。
**問題が出るたびにここを直す。**

作図（`.qet` を描く）側の勘所は別のスキル `qelectrotech` にある。

---

## 一つ描くときの手順

```bash
py -3 tools/status.py --next 10        # 次の番号と規格票のページ
```

1. 規格票のそのページを測る（下の「規格票を測る」）
2. `tools/elmtgen.py` を使う生成スクリプトを**スクラッチパッドに**書いて `.elmt` を吐く
   置き場所は `elements/JIS_C_0617/<節>/<番号>.elmt`。**節のフォルダ名もASCII**
3. `py -3 tools/render_elmt.py <番号>` で**目視**。規格票の切り出しと見比べる
4. `py -3 tools/check_elmt.py` で**機械の点検**。目視で出ない不備を拾う
5. `py -3 tools/status.py` → `git commit` → `git push`

**3 と 4 は両方かける。役割が違う。**
目視は「形が規格どおりか」、`check_elmt.py` は「外形・端子・属性が壊れていないか」。

## QET で表示が壊れる条件（**知らないと必ず踏む**）

| やってしまうこと | QET でどうなるか |
|---|---|
| **ファイル名に日本語** | 記号名が `<name lang="ja">` ではなく**ファイル名（拡張子つき）に化ける** |
| **フォルダ名に日本語** | `qet_directory` が読めず、部品パネルで**フォルダ名が空欄**になる |
| **外形 10×10** | プレビューを作れない。ログに `QPainter::begin ... engine == 0` |
| **文字が外形からはみ出す** | 動かしたとき**画面にゴミが残る**（再描画は外形の矩形だけ） |
| **外形が10の倍数でない** | 同梱8597個すべてが10の倍数。実装側の要求と見てよい |

**どれも `.elmt` を絵にしただけでは分からない。** `check_elmt.py` が全部弾く。

## 文字

**`1em = ポイント数 × 96/72`。** Qt が pt を画素に直す比。

**記号の中の文字は 4〜10 pt に収める。** 同梱コレクション23,010個の分布は 2〜9
（最多は 5・6・4・9）。10を超えたら疑う。

> かつて `1em = 0.78 × pt` と誤っていた。**QET では1.7倍**になり、
> 文字が外形からはみ出して画面にゴミが残った。
> **描き出し側と生成側が同じ係数で間違えていたので、目視でも検査でも通ってしまった。**
> 数式を疑うときは**同梱コレクションの統計と突き合わせる。**

### `<text>` と `<dynamic_text>` の使い分け

| | 用途 | 座標の意味 | 回すと |
|---|---|---|---|
| `<text>` | 記号の一部（`Θ` `V` `I >`） | **ベースラインの左端** | 一緒に倒れる |
| `<dynamic_text>` | ラベル欄、編集させたい値 | **外接矩形の左上** | `keep_visual_rotation` 次第 |

置き換えるときは **`y_上端 = y_ベースライン − 0.905 × em`**。

- **ラベル（`text_from="ElementInfo"`）は `keep_visual_rotation="true"`。** 倒しても正立
- **記号の中の文字は倒れてよい。** 決めてある（`docs/寸法基準.md`）
- **規格票が「例」として示している値**（`5…10 A` など）は
  `text_from="UserText"` にして図面上で書き換え・削除できるようにする。
  **`I >` のような定義そのものの記号は静的な `<text>` のまま**

### link_type —— 接点は自分がスレーブだと宣言する

**`.elmt` が持つのは役割だけ。**どのコイルとどの接点が対かは `.qet` 側にある。
だが**役割を書いていないと相互参照そのものが張れない。**

| | 例 | link_type |
|---|---|---|
| ラベルをマスタから取る**接点** | a接点、限時接点 | **`slave`** |
| **接点を別の場所に描く側** | 継電器コイル | **`master`** |
| それ自体が機器（**接点を内蔵**して1つで完結） | 押しボタン、リミットスイッチ、温度スイッチ | `simple` |
| 限定図記号（端子を持たない） | 接点機能 | `simple` |

**「接点」と名が付いていても機器なら `slave` ではない。**
逆に、純粋な接点を `simple` のままにするとラベルが同期されない（実際にやった）。

## 弧の角度

| | 0度の向き | 正の角度 |
|---|---|---|
| QET / Qt | 3時方向 | **反時計回り** |
| Pillow | 3時方向 | **時計回り** |

`.elmt` には **QET の流儀**で書く。`render_elmt.py` が反転して描く。

**弧を外接矩形で判定してはいけない。** 楕円の通らない側まで数えて必ずはみ出す
（`check_elmt.py` は実際に通る点を32分割で出している）。

## 規格票を測る

規格票は**リポジトリの外**（`%USERPROFILE%\規格\`）。`.gitignore` で二重に弾いている。
**図版も PDF もリポジトリに入れない。**

`tools/measure_page.py` がリポジトリ側の測定ツール。細かく測る使い捨ての道具は
スクラッチパッドに作る（`probe.py` / `zoomp.py` など。セッションごとに作り直してよい）。
やることは同じ。

- ページを 600dpi でラスタライズ
- ドット格子を拾って **1M が何ピクセルか**出す（**1M = 10 単位**）
- 指定した y の行を走査して、暗い画素の区間を M 単位で吐く

### 測るときの落とし穴

- **縦横で縮尺が違う。** 表のセルに入っているせいで列と行の間隔が最大6%ずれる。
  **必ず別々に測る**
- **1目を「間隔の中央値」で決めてはいけない。** ドットは図に隠れて飛ぶし、
  図の小さな部品や表の切れ端がドットに混じる。中央値も最頻値もそれに引きずられ、
  あるページで **1M が半分**に、別のページで **7% 大きく**出た。
  **周期そのものを合わせる**（Σ exp(2πi x/p) の大きさが最大になる p を探す）。
  ドットが欠けても余計な点が混ざっても効く
- **図の帯は「横罫線と横罫線のあいだ」。**最初の罫線で切ると、表の見出し行の
  罫線が図より上にあるので図ごと落ちる。罫線を連結成分として拾おうとしても、
  表の枠は全部つながっているので拾えない。**行ごとに暗い画素の連続の長さを見る**
- **帯をドットの数だけで選ばない。** 説明表の句読点が図のドットより多いページがあり、
  表のほうを図と取り違えた。**格子らしさ（周期のそろい具合）で重みを付ける**
- **ドットは「孤立しているか」で判定しない。** 図に寄ったドットは孤立判定に落ち、
  そのまま墨に数えられて図の外形が上下左右に最大1Mずつ膨らむ。
  **大きさだけで外す**
- **走査の刻みを粗くすると線を見落とす。** `y=4.0` ちょうどにある破線を
  0.2刻みで2ページ分見落とした。**節目の座標は必ず踏む**
- **測定メモを鵜呑みにしない。** 描く前にそのページをもう一度走査する
- **限定図記号の中をリード線が通らないことがある。**
  行走査で中心の x に暗い画素が無いかを見れば分かる
- **規格票にリード線が無い図記号がある。** 外形の縁に端子を足し、
  足したことを `<informations>` に必ず書く

## 寸法・端子

詳細は `docs/寸法基準.md`。要点だけ。

- グリッド **10**。これは規格の作図モジュール **M** と一致する（実測で確認）
- 端子間は**縦置きの機器 60**（`y = ±30`）／**端子・ジャンクション 30**（`y = ±15`）
- `hotspot` は既定で外形の中央。左右非対称なら `hx` をずらす
- 端子には **`uuid` `name` `type="Generic"` `orientation`** が必須
- **`<terminal>` の並び順を後から変えない。** 出現順に id が振られ、
  既に作った `.qet` の導体のつながり先がずれる
- **可動接片の角度は規格票がページごとに揺れている。** 揃えると決めてある。
  `docs/寸法基準.md` の表に従い、ページの値をそのまま採らない

## 規格票が「例」でしか示していないもの

規格票は1つの例しか載せていないが、実務では**数が変わる**ものがある
（多段スイッチの位置の数、継電器の動作値など）。

| 変わるもの | 直し方 |
|---|---|
| **値・文字** | `<dynamic_text text_from="UserText">` にして図面上で書き換えられるようにする |
| **形**（段数・極数） | **別ファイルとして起こす。** 編集では変えられない |

形を増やすときは、**規格票の例をその規則で再現できるか**を必ず確かめる。
07-11-06（多段スイッチの位置図）は「一番外の光線を ±40 度に置いて等間隔に割る」
という規則にしたら、4位置が規格票の実測（±19°・±40°）と一致した。
**一致しない規則なら読み違えている。**

## 直すとき

**生成し直さず XML を書き換える。** 生成し直すと `uuid` が変わり、
既に作った `.qet` の参照が切れる。図形も端子も原点基準なので、
外形と `hotspot` を広げるだけなら座標は触らなくてよい。

## 実機で見る

```bash
py -3 tools/install.py
```

- **これは依頼者自身のターミナルで叩いてもらう。**
  Claude Code の環境からだとリポジトリの外への書き込みが実ディスクに届かない。
  たちの悪いことに書いた直後に読み返すと自分が書いたものが見えるので、
  **成功したように見える**
- **フォルダ構成を変えたときは先に `--uninstall`。** でないと古い名前が残って二重に並ぶ
- QET は**スタートメニューから起動**する（exe 直叩きは部品0個）
- **QET のログは読める** —— `%APPDATA%\qelectrotech\QElectroTech\<日付>.log`。
  起動ごとに `Custom Elements count` と警告が出るので、入れ直しの結果を確かめられる

## 心構え

- **症状を1つの原因で説明しようとしない。** 「フォルダ名が空」と
  「記号名がファイル名になる」は別々の原因だった。片方を直しても片方は残る
- **仮説を「外れ」と早々に切らない。** 依頼者の指摘が正解だったのに一度否定した
- **「入れておきました」と言わない。** 実ディスクに届いたか確かめられない

# tools/ の使い方

`tools/` の Python ツールの説明。

| ファイル | 何をする | 入力 | 出力 |
|---|---|---|---|
| `paths.py` | 図記号と規格票 PDF の在りかを解決する（他が使う） | — | — |
| `elmtgen.py` | `.elmt` を座標から組み立てる | 座標 ＋ Python | `.elmt` |
| `render_elmt.py` | `.elmt` を PNG に描き出す（`marks=False` で姿だけ） | `.elmt` | `render/` に PNG |
| `check_elmt.py` | `.elmt` を検証する | `.elmt` | 標準出力＋終了コード |
| `qetgen.py` | `.qet` をコードから組み立てる | `.elmt` ＋ Python | `.qet` |
| `check_qet.py` | `.qet` を検証する | `.qet` | 標準出力＋終了コード |
| `pdf_page.py` | PDF のページを画像に描き出す | `.pdf` | **リポジトリ外**に PNG |
| `stdpage.py` | 規格票のページから図の帯と作図モジュールの格子を取り出す | ページ番号 | 標準出力／**リポジトリ外**に PNG |
| `compare_page.py` | 描いた記号を規格票と突き合わせる | `.elmt` ＋ 規格票 | 標準出力／**リポジトリ外**に PNG |
| `status.py` | 採録状況を `elements/` から数え直す（`--part` で部を選ぶ） | `elements/` | `docs/採録状況*.md` |
| `svg_elmt.py` | `.elmt` を SVG に写す（人に見せる姿） | `.elmt` | `render/` に SVG |
| `mkindex.py` | 図記号番号→ページの索引を規格票から作り直す | 規格票 | `docs/規格データ/` |
| `sympage.py` | 図記号1個1枚の HTML と目次・注釈を作る | `elements/` ＋ 注釈 tsv | `docs/sym/` |
| `cheatsheet.py` | 印刷用の早見表を作る | 選んだ記号 | `docs/チートシート.svg` |
| `install.py` | 図記号を QET に登録する（**「CADにしない」は入れない**） | `elements/` ＋ `docs/sym/` | ユーザーコレクション |

> **`docs/規格データ/` は文書ではない。**規格票から採った作業用のデータ
> （索引・注釈の要点・注釈の適用先）で、道具が読む。置き場は `paths.STDDATA`。

**どのフォルダから叩いてもよい。** リポジトリの位置は `paths.py` の場所から求めるので、
どこに clone しても、カレントディレクトリがどこでも動く。

記号そのものをどう描くかは [寸法基準.md](寸法基準.md)。
**`.elmt` と `.qet` の XML の構造**は [QETのXML.md](QETのXML.md)。

## 共通の前提

- Python 3.9（`py -3`）

  ```bash
  py -3 -m pip install pillow pypdfium2
  ```

  | ライブラリ | 使うツール | ライセンス |
  |---|---|---|
  | `pillow` | `render_elmt.py` | MIT-CMU |
  | `pypdfium2` | `pdf_page.py` | BSD-3-Clause / Apache-2.0 |

  **依存は permissive なものだけにする。**
  PDF の描画は PyMuPDF のほうが手軽だが **AGPL-3.0**（または商用）で、
  公開リポジトリに置くツールが強い copyleft の義務を負う。
  上流の CC-BY を避けて記号を描き起こしているのに、依存側で義務を拾っては意味がない。

- 3本とも `.elmt` の同じところを見る

  | 場所 | 意味 |
  |---|---|
  | `<definition>` の `width` `height` | 部品の外形の大きさ |
  | `<definition>` の `hotspot_x` `hotspot_y` | 外形の左上から見た原点の位置 |
  | `<definition>` の `link_type` | `master`（コイル）/ `slave`（接点）/ `simple` |
  | `<terminal>` の `x` `y` `orientation` `uuid` `name` `type` | 端子。導体はここにしかつながらない |
  | `<name lang="ja">` | 日本語名。描き出しのキャプションと `.qet` の部品名になる |
  | `<informations>` | 図記号番号などの覚え書き |

- **端子の向き** は `n` `e` `s` `w`。`.qet` の中では `0` `1` `2` `3` の数値になる
  （[qetgen.py:28](../tools/qetgen.py#L28) の `ORI`）

- **端子には定義ファイルの出現順に id 0, 1, 2… が振られる**
  （[qetgen.py:66](../tools/qetgen.py#L66)）。
  すでに `.qet` を作った後で `.elmt` の `<terminal>` の順番を入れ替えると、
  **その `.qet` の導体のつながり先がずれる。** 端子は足すなら末尾に足す。

## paths.py — 記号の探し方

3本が共通で使う。**探索先はここ1か所にしかない**ので、増やすときはこのファイルだけ直す。

### 探索の順番

1. 環境変数 `W_QET_ELEMENTS`（区切りは Windows なら `;`。複数指定できる）
2. `<リポジトリ>/elements`
3. QET のユーザーコレクション `%APPDATA%\qelectrotech\QElectroTech\elements`

**いずれも再帰的に探す。** `elements/` の下をどうフォルダ分けしても、記号は名前だけで見つかる。
同じファイル名が複数あれば**先の探索先が勝つ**（`W_QET_ELEMENTS` で一時的に差し替えられる）。
入れ子の深さは優先順位に影響しない。`elements/JIS_C_0617/07-02/07-02-01.elmt` は、
ユーザーコレクション直下の同名ファイルに勝つ。

> **ここは効いてくる。** QET のユーザーコレクションには、以前の案件で使った記号が
> 同じ名前で残っている場合がある。それらは上流コレクションから変換したもので、
> ライセンス上の理由でこのリポジトリからは破棄した（CLAUDE.md「絶対に守ること 1」）。
> `elements/` が先に来るので**自分で描き起こしたものが必ず勝つ**が、
> `elements/` にまだ無い名前は**ユーザーコレクション側が拾われる**。
> `--all` は `elements/` しか見ないので、ここは混ざらない。

### 記号の指定のしかた

どのツールでも次の形を受け付ける。

| 書き方 | 例 |
|---|---|
| パス | `elements/JIS_C_0617/07-02/07-02-01.elmt` |
| ファイル名 | `07-02-01.elmt` |
| 拡張子なし | `07-02-01` |
| サブフォルダ付き | `07-02/07-02-01`（区切りは `/` `\` どちらでも） |

見つからないときは、**探した場所を全部並べて** `FileNotFoundError` になる。

```
存在しない記号 が見つからない。探した場所:
  C:\Users\kouic\source\repos\w-qet\elements
  C:\Users\kouic\AppData\Roaming\qelectrotech\QElectroTech\elements
（環境変数 W_QET_ELEMENTS で探索先を足せる）
```

### API

| | |
|---|---|
| `find(name)` | 名前かパスから `.elmt` の実体を返す |
| `table()` | `{ファイル名: フルパス}`。探索先を再帰的に走査した結果（キャッシュあり） |
| `collection()` | `elements/` にある `.elmt` のパス一覧 |
| `search_dirs()` | 実在する探索先を優先順に |
| `ELEMENTS` `RENDER` | `<リポジトリ>/elements` と `<リポジトリ>/render` |
| `standard(part)` | 規格票 PDF のパス。`W_QET_STD` → `~\規格\` の順に探す |
| `std_dirs()` | 規格票を探す場所を優先順に |
| `index(part)` | 図記号番号 → 規格票のページ（`docs/規格データ/第<part>部索引.tsv`） |

### 規格票 PDF もここで解決する

**買った規格票はリポジトリに入れない**（公開リポジトリなので再配布になる）。
置き場所は人によって違うので、**パスをソースに書かない。**

```
1. 環境変数 W_QET_STD（フォルダでもファイルそのものでもよい）
2. ~\規格\ ／ ~\Documents\規格\ の jis_c_00617_<部>_*.pdf
```

`standard()` を使うツール（`stdpage.py` `compare_page.py`）は、
**出力もリポジトリの外**（`%TEMP%\w-qet-pdf\`）に書く。

## render_elmt.py — 描いた記号を目視する

QET を起動しなくても記号の見た目を確認できる。
**座標を読むだけでは形の誤りに気づけない**ので、記号を作ったら必ずこれを通す。

### 使い方

```bash
py -3 tools/render_elmt.py 07-02-01
```

複数渡すと1枚の画像に最大4列で並べる。記号どうしの寸法を見比べるときに使う。

```bash
py -3 tools/render_elmt.py 07-02-01 07-02-03
```

`elements/` にある記号を全部描く。

```bash
py -3 tools/render_elmt.py --all
```

出力先は `<リポジトリ>/render/`。1個なら `<名前>.png`、複数なら `sheet.png`。
`render/*.png` は `.gitignore` 済み。

終了コードは、記号が見つからない・`elements/` が空のとき `1`。

### 画像に何が描かれるか

| 見た目 | 意味 |
|---|---|
| 薄いグレーの長方形 | 部品の外形枠（`width` × `height` を `hotspot` で置いたもの） |
| 赤い十字 | 原点。**端子は原点対称に置く** |
| 赤い丸＋文字 | 端子と、その向き（`n` `e` `s` `w`） |
| **青い文字＋十字** | `<dynamic_text>`＝ラベル欄の置き場所。`[label]` は図面で機器記号に差し替わる欄 |
| 下1行目 | ファイル名＋`<name lang="ja">` |
| 下2行目 | `<informations>` の中身 |

外形枠と原点が見えるので、**端子が枠から外れている・原点がずれている**のはここで分かる。
ラベル欄が青いのは、図形ではないものを図形と見間違えないため。

拡大率は1単位=4px（`S`）、余白 40px（`PAD`）。[render_elmt.py:35-36](../tools/render_elmt.py#L35) で変えられる。

### 解釈するもの

- プリミティブ：`line` `polygon` `arc` `ellipse` `circle` `rect` `text` `dynamic_text`
- `line-style`：`normal` `dashed` `dotted` `dashdotted`
- `line-weight`：`thin`(1px) `normal`(2px) `hight`・`eleve`(4px) `none`(描かない)
- `filling`：色名をそのまま塗る
- `<line>` の端末装飾 `end1` `end2`：`simple` `triangle` `circle` `diamond`（`length1` `length2` で大きさ）

`polygon` は `closed="false"` なら折れ線、既定（`true`）なら閉じた多角形。

`circle` は `x` `y` `diameter` を持ち、**`x,y` は中心ではなく外接矩形の左上**
（`ellipse` と同じ）。読み込み時に `ellipse` へ正規化している。
自分で描くぶんには `ellipse` だけ使えばよく、`circle` は QET のエディタで描いた記号や
既存の `.elmt` を読むときに出てくる。

`<text>` の大きさは 0.100 では `font="Liberation Sans,9,…"` の2番目の数字。
旧形式の `size="9"` も拾う。

端末装飾の作図は QET の `partline.cpp` に合わせてある。端点から線上に `length` の点を O、
`2×length` の点を A、O から直交して ±`length` の点を B・C として、
`simple` は C→端点→B の折れ線、`triangle` は B・端点・C の塗り三角、
`circle` は O 中心・半径 `length` の円、`diamond` は A・B・端点・C の菱形。

### 円弧の角度の約束

**ここは間違えやすい。**

| | 0度の向き | 正の角度 |
|---|---|---|
| QET / Qt | 3時方向 | 画面上で**反時計回り** |
| Pillow | 3時方向 | 画面上で**時計回り** |

そのため描き出し側で向きを反転している（[render_elmt.py:219](../tools/render_elmt.py#L219)）。

```
pil_start = -(qt_start + qt_span)
pil_end   = -qt_start
```

`.elmt` に書く `start` / `angle` は **QET の流儀**（反時計回り）。

## svg_elmt.py — 人に見せる姿を出す

`render_elmt.py` の PNG は**自分が確かめるための道具**で、外形枠・原点・端子の印を
一緒に描く。`svg_elmt.py` は**人に見せる姿だけ**を出す。`sympage.py` と `cheatsheet.py` の土台。

```bash
py -3 tools/svg_elmt.py 07-02-01                  # render/07-02-01.svg
py -3 tools/svg_elmt.py --sheet 07-02-01 07-02-03 # 並べて1枚
py -3 tools/svg_elmt.py --marks 07-02-01          # 外形と端子も描く（確認用）
```

**なぜ SVG か。**テキストなので git の差分が効き（PNG は中身が見えない）、
GitHub の Markdown がそのまま表示し、拡大しても崩れないので印刷に使える。

読み取りは `render_elmt.parse()` を**使い回している**。あちらが踏んだ落とし穴
（`circle` の x,y は左上／実体参照を戻す／`font=` と `size=` の両方を拾う）を
書き直すと踏み直す。

### 描き出しで気をつけたところ

- **弧の向き。** SVG の sweep フラグは 1 が時計回り。QET の正の角度は反時計回りなので
  **正の angle には sweep=0**。全周は始点と終点が重なってパスが消えるので `<ellipse>` にする
- **`<text>` と `<dynamic_text>` の y の意味が違う。** 前者はベースライン（SVG の既定と同じ）、
  後者は外接矩形の上端。そのまま渡すと 1em ぶん上にずれる
- **規格票が「例」として示す値**（`5…10 A` など）は `text_from="UserText"` に入っている。
  **これは描く。** QET に置いたときに既定で出るものなので、落とすと実物と食い違う。
  ラベル欄（`ElementInfo`）は図面で埋まる空欄なので描かない
- **並べるときセルの大きさを全体の最大で決めない。** 07-12-06（110×140）が1つあるだけで
  a接点（20×60）の周りが余白だらけになる。**列の幅は列の最大、行の高さは行の最大**
- **キャプションは文字数で切らない。** 和名は幅の狭い列で必ず隣とぶつかる。
  和字1em・英数0.55em で測って**セル幅で切る**

## sympage.py — 図記号1個1枚の頁と、目次・注釈のページを作る

```bash
py -3 tools/sympage.py
```

`docs/sym/` に、**図記号1個につき1枚の HTML** ＋ 目次（`index.html`）＋
規格の注釈（`notes.html`）＋ 姿だけの SVG（`svg/*.svg`）を作る。**公開用。**

**外部の CSS・JS・画像を使わない。** GitHub Pages でも `file://` でも、
1枚だけ人に渡してもそのまま開ける。

### 1枚に何が載るか

| | |
|---|---|
| 姿 | 1M の格子・外形の枠・端子の印つき。**格子は原点に位相を合わせてある** |
| 諸元 | 外形／挿入基点／役割／端子の数／図形の数 |
| 規格の注釈 | その図記号に付いている注釈。要点＋`notes.html` へのリンク |
| 図記号ファイルの覚え書き | `.elmt` の `<informations>`（自動。書き換えても消える） |
| **覚え書き** | **人が手で書く欄**（下） |
| **この図記号から何を作るか** | **人が手で書く欄。**CAD用シンボルにするか／組合せ。**同じ種類の判断なので隣に置く** |
| 他の形式に写すときの約束 | 単位・y の向き・弧の角度・線の太さ・書体 |
| 機械可読 JSON | **座標はここにしかない。**円は中心と直径、弧は中心と角度、と**形式に依らない形**に直してある |

### 手で書く欄は作り直しても消えない

```html
<!--hand:memo-->  ここに書く  <!--/hand:memo-->
```

`memo`（覚え書き）・`cad`（CAD用シンボルにするか）・`combine`（組合せ）の3つ。
**`cad` と `combine` は「この図記号から何を作るか」で1つの節にまとめてある。**
`sympage.py` は書き出す前に既存の頁からこの中身を読み戻す
（生成物の中に人の書き込みを残す、という同じ考え）。

**`cad` の答えは頁にしか書かない。** Claude が規格票から判断して書くことも、
人が判断して書くこともあるが、**置き場を分けると二重管理になる**ので
どちらも同じ場所に書く。既定は「する。」。

**「する。」か「しない。」で書き始める。** `status.py` はそこだけ見て数える
（`paths.cad_policy()` が `docs/sym/*.html` を走査する）。

> **これは頁を見た人（や Claude）が読むための項目。**
> 「しない」と書いてあれば CAD 用のシンボルを作らなくてよい、という合図で、
> **図（SVG）とこの頁は作らないものにも用意する。**

- **印（`<!--hand:…-->`）を消さないこと。** 消えると読み戻せない
- 置いてある「（例：…）」は、何か書けば自動で消える
- 記号ごと消したときは、その頁に手書きがあれば**名前を出して知らせる**

### 規格票 PDF は要らない

規格から採った情報は `docs/規格データ/第<N>部注釈.tsv`（要点）と
`docs/規格データ/第<N>部注釈_適用.tsv`（適用先）に落としてある。**会社PCでも作り直せる。**

> **規格票の本文を写さない。**注釈のページに載せるのは、番号・**こちらの言葉での
> 要点**・適用される図記号へのリンクだけ（CLAUDE.md の 1・2・5）。

## mkindex.py — 索引を規格票から作り直す

```bash
py -3 tools/mkindex.py --part 7            # 突き合わせ（差があれば終了コード1）
py -3 tools/mkindex.py --part 7 --write    # docs/規格データ/第7部索引.tsv を作り直す
```

**索引を手で作らない。** 手で作ったせいで第7部の索引が附属書A の途中で切れ、
**19個を丸ごと落としたまま `status.py` が 161/161 と嘘の採録率を出していた**
（実際は 161/180）。分母を手で作ると、足りないことに気づく手立てが無くなる。

| やってしまうこと | どうなるか |
|---|---|
| 「図記号番号」という語だけでページを選ぶ | 巻頭の表1（項目名の説明）を拾う。07-01-01 が p.7 と誤判定された |
| 番号だけを見て拾う | 巻末の注釈の節にも番号がずらりと並ぶ |

**番号のすぐ後ろに識別番号（`（S00227）`）が続くページ**だけを図記号のページとみなす。

## cheatsheet.py — 印刷用の早見表を作る

```bash
py -3 tools/cheatsheet.py
```

`docs/チートシート.svg`（A4 縦1枚）。**`docs/sym/` とは役割が違う。**
あちらは**ぜんぶ**を1個1枚で出すもの、こちらは**よく使うものだけ**を
機能ごとにまとめ、作図中に手元で番号を引くためのもの。

載せるものはスクリプトの `GROUPS` が持つ。**足すときは何かを落とす。**
1枚に収まらなくなったら終了コード1で知らせる（`使った高さ` を出す）。
第8部（表示灯・ブザー・指示計器）を載せるとき、始動器（07-14）を落とした。
**いま 296mm / 297mm で空きが無い。**

記号の姿だけでは分からない決めごと（端子間・コイル大文字と接点小文字・
導体は端子の間にしか引けない）を `NOTES` に載せてある。**これがあるから1枚で用が足りる。**

## check_elmt.py — 目視で見つからない誤りを拾う

```bash
py -3 tools/check_elmt.py            # elements/ を全部
py -3 tools/check_elmt.py 07-02-01   # 名前・番号・パスで絞る
```

**`render_elmt.py` の目視と役割が違う。** 目視は「形が規格どおりか」を見るもので、
外形・端子・属性の不備は絵に出ない。**両方かける。**

見るもの。

- 外形が10の倍数か。`hotspot` が外形の中か。`link_type` が既知の4つか
- 端子の `uuid` `name` `type="Generic"` `orientation` `x` `y`。端子名と uuid の重複
- **図形が外形に収まっているか。**線・矩形・円・多角形・文字、そして弧
- 記号どうしの uuid 重複、`<name lang="ja">` と `en`
- ラベルの `keep_visual_rotation="true"`
- `JIS_C_0617/` の下は図記号番号があってファイル名と一致するか。
  **その外に規格の行が紛れ込んでいないか**（出所を偽ることになる）
- **規格に番号の無い組合せ**（ファイル名に `+`）は、番号の行ではなく
  「`JIS C 0617 の組合せ A ＋ B`」を持つか。**組合せ元が実在するか**
  （[寸法基準.md](寸法基準.md)「規格に番号の無い組合せ」）
- **`elements/` 以下のパスに非ASCIIの文字が無いか。**
  日本語のファイル名だと QET が記号名を読めず、日本語のフォルダ名だと
  `qet_directory` を読めない（[寸法基準.md](寸法基準.md)）
- **外形が 10×10 になっていないか。**QET がプレビューを作れない

問題があれば終了コード 1。

> **弧は外接矩形で見てはいけない。** 楕円の通らない側まで数えて必ずはみ出す。
> 実際に通る点を32分割で出して見ている。

> **文字は実際のフォントで描いて測る**（Arial。Liberation Sans と字幅互換）。
> 送り幅の表で見積もっていたが、空白や記号を取りこぼすうえ、上下の高さは
> em の割合で当てるしかない。**外形からのはみ出しは画面にゴミが残る**ので、
> ここは実測でないと意味がない。フォントが読めない環境では表（`ADV`）に落ちる。
>
> **1em = `ポイント数 × 96/72`**（Qt が pt を画素に直す比）。ここを 0.78 と
> 誤っていて、**QET では1.7倍の大きさになっていた。**
> プレビューだけ正しく見えるので気づけなかった。

これを入れたときに、目視では気づけなかった17件が出た。
外形が10の倍数でないもの13個、外形からはみ出した図形2個、端子名の重複1件、
規格外の部品に規格の行が入っていたもの1件。

## stdpage.py — 規格票のページを測る

規格の図には**作図モジュール M のドット格子**が添えられている。これを検出すれば
図形の座標が M 単位で読め、**1M = 10** なので10倍すれば `.elmt` の座標になる。

```bash
py -3 tools/stdpage.py 78            # 格子と、図の墨の成分を M で並べる
py -3 tools/stdpage.py 78 --rows     # 行走査（斜線の折れ点を見る）
py -3 tools/stdpage.py 78 --png      # 図だけ切り出して保存
```

出力先は `%TEMP%\w-qet-pdf\`。**リポジトリには一切書かない。**

### 規格票 PDF の在りか

`paths.standard(part)` が解決する。**パスをソースに書かない。**

1. 環境変数 `W_QET_STD`（フォルダでもファイルそのものでもよい）
2. `~\規格\` / `~\Documents\規格\` の `jis_c_00617_<部>_*.pdf`

### ライブラリとして使う

```python
import stdpage
p = stdpage.Page(78)
p.mx, p.my        # 1M が何ピクセルか（**縦横で違う**）
p.ink             # 図形の連結成分。ドットは除いてある
p.size            # 墨の (幅M, 高さM)
p.toM(x, y)       # ピクセル → 墨の左上を原点とする M
p.scaled(40)      # 1M=40px にそろえた切り出し
p.rows(0.2)       # 行走査
p.ok              # 格子が取れたか（07-16-02〜07-16-10 と 07-A11-01 は False）
p.scale           # 図の倍率。`200 %` のページは 2.0（mx/my に反映済み）
```

**使い捨ての測定スクリプトを書く前にこれを import する。**
下の落とし穴はすべてここで処理済みで、書き直すと踏み直す。

### 素朴に書くと必ず外すところ

| やってしまうこと | どうなるか |
|---|---|
| **1目を隣どうしの差から決める**（平均・中央値・最頻値） | 図に隠れて飛んだドットや、混じった小さな部品に引きずられる。**あるページで 1M が半分、別のページで 7% 大きく**出た |
| ページ内の**決め打ちの割合**で図を切り出す | 背の高い図（14M・17M）が切れる |
| **最初の横罫線**で下を切る | 表の見出し行の罫線が図より上にあり、図ごと落ちる |
| 罫線を**連結成分**として拾う | 表の枠が全部つながっていて拾えない。**行ごとに暗い画素の連続の長さ**を見る |
| 帯を**ドットの数**だけで選ぶ | 説明表の句読点のほうが多いページがあり、表を図と取り違える |
| ドットを**孤立しているか**で判定する | 図に寄ったドットが墨に数えられ、図の外形が上下左右に最大1Mずつ膨らむ |
| 縦横を**同じ縮尺**とみなす | 図が表のセルに入れられていて、実測で最大6%ちがう |
| **どのページも等倍**とみなす | 小さい図記号は2倍に拡大して刷ってあり、図記号欄に `200 %` と付く。**ドットは拡大されない**ので、気づかないと倍の大きさの記号を作る。`200 %` の文字も墨に数えられて外接矩形が伸びる |
| ページ内の `NNN %` を**どれでも**倍率と見る | 説明欄にも「再設定比は 130 %」のような数字＋% が出る。**図の帯の中にあるものだけ**を採る |

1目は**周期そのものを合わせて**出す（|Σ exp(2πi x/p)| が最大の p）。
ドットが欠けても余計な点が混ざっても効く。

**格子の無いページがある。**第7部では 07-16-02〜07-16-10 の9枚と 07-A11-01 の計10枚、第8部には無い（全180＋67ページを走査して確かめた）。そこで拾った「ドット」は説明表の句読点なので
周期に乗らない。**そろい具合で切る** —— 実測で、格子のあるページは縦横とも 1.00、
無いページは 0.36〜0.48。`ok` が False のときは `cell()` が図記号のセルだけ返すので、
縮尺は合わないが目で見比べられる。

## compare_page.py — 描いた記号を規格票と突き合わせる

```bash
py -3 tools/compare_page.py 07-02-01 07-02-03    # 並べた画像
py -3 tools/compare_page.py --num 07-02-01       # 数値だけ
py -3 tools/compare_page.py --num --all          # 全件（数分かかる）
```

規格票の図とこちらの記号を **1M = 40px** にそろえて並べ、
**墨の載っている範囲**（外形ではない）を数値で出す。0.2M 以上ちがうと `★ちがう`。

こちら側の墨は**画像ではなく `.elmt` から**出す。描き出した画像には外形枠と
端子の印が入っているので、画像から測ると外形まで数えてしまう。

**出力先は `%TEMP%\w-qet-pdf\`。** 並べた画像には規格票の図が入るので、
公開リポジトリに置くと再配布になる。

### 数値がちがう＝誤り、ではない

**仕分けてから直す。順番を間違えると正しい記号を壊す。**

| 仕分け | 見分け方 |
|---|---|
| **測り方の誤り** | **まずこれを疑う。** 上の「素朴に書くと必ず外すところ」 |
| **決めごとどおり** | 引出し線の長さ（端子間 60）・可動接片の角度。[寸法基準.md](寸法基準.md) |
| **規格票に図が複数** | 向きちがいを2つ並べているページがある |
| **規格票に格子が無い** | 07-16-02〜07-16-10 と 07-A11-01 の10枚。`—` と出る。目視だけ |
| **本当の誤り** | 上のどれでもないとき |

> 「要修正」と判断した2件が、格子の測り直しで**どちらも正しかった**。
> 道具を疑う前に記号を疑って、直しかけた。

### 数値に出ないもの

- **規格票の説明欄に書いてあるのに描いていない部品。**
  補足事項（部品の一覧）と形状分類（「点」「線」など）を読む
- **書体。** 規格票は変数をセリフ斜体で組む。こちらは Liberation Sans。
  **形は合わせるが書体は合わせない**と決めてある

## qetgen.py — .qet をコードから組み立てる

`.qet` は XML。手描きした `無題.qet` を解析して分かった仕様に基づいて組み立てる。
ライブラリなので単体では動かさず、`import` して使う。

### 最小の例

```python
# -*- coding: utf-8 -*-
import sys
sys.path.insert(0, "tools")        # リポジトリの tools/ を見えるようにする
import qetgen

f = qetgen.Folio("主回路", cols=17, rows=8, colsize=60, rowsize=80)

coil = f.add("40_リレーコイル", 300, 200, "R1")      # 部品を置く
ctc  = f.add("30_a接点",       300, 500, "r1")      # その接点
f.wire(coil, "s", ctc, "n", num="1")                # 端子どうしを導体で結ぶ
ctc.link_to(coil)                                   # 接点をコイルに紐づける

qetgen.save("出力.qet", [f], title="制御盤")
```

図枠の大きさは `cols × colsize` × `rows × rowsize`。上の例なら 1020 × 640。

`f.add()` に渡す名前は `paths.py` が解決する。`elements/` のどのサブフォルダにあってもよい。

### クラス

| クラス | 役割 |
|---|---|
| `Part` | `.elmt` を読んで保持する。`Part.get(名前)` はキャッシュ付き |
| `Inst` | 図面に置いた部品1個。`Folio.add()` が返す |
| `Cond` | 導体1本。`Folio.wire()` が返す |
| `Folio` | 図面1ページ |

`Part.term(which)` は `'n'` `'e'` `'s'` `'w'` の向き指定か、端子の index（int）を取る。
`Folio.wire()` の第2・第4引数がこれ。

**同じ向きの端子が複数ある部品を向きで指定するとエラーになる。**
黙って先頭を返すと配線先を取り違えたまま図面が出来上がるため。
index を使えという指示と、候補の index がメッセージに出る。

```
_2端子同向き.elmt には向き n の端子が 2 個ある（index [0, 1]）。index で指定すること
```

### 部品定義は .qet に埋め込まれる

`save()` は、使った `.elmt` の中身を丸ごと `<collection><category name="import">` に入れる。
部品側は `embed://import/<ファイル名>` で参照する（[qetgen.py:271](../tools/qetgen.py#L271)）。

**他の PC で開いても部品が失われない**のがこの方式を採っている理由。
参照名は**ファイル名だけ**なので、`elements/` をどうフォルダ分けしても `.qet` の中身は変わらない。
`save()` の戻り値は埋め込んだ部品定義の種類数。

### 接点のラベルは UserText にする

**ここは QET の癖で、知らないと必ずはまる。**

`link_type="slave"` の部品（接点）のラベルは、リンク先のコイル（master）から QET が自動同期する。
接点に `"r1"` と書いても、コイルの `"R1"` で上書きされて表示される。

そこで、**ラベルを付けたスレーブは `text_from="UserText"` に切り替えている**
（[qetgen.py:127-131](../tools/qetgen.py#L127)）。表示だけマスタから独立し、
相互参照そのものは `links_uuids` 側なので保たれる。

日本の慣習で コイル `R1` / その接点 `r1` と書き分けるために要る。

### そのほか

| | |
|---|---|
| `Folio.rect(x1,y1,x2,y2)` | 矩形。**既定は破線**（盤の外郭を示す慣用） |
| `Folio.text(x,y,s,pt,bold)` | 図面上の独立テキスト |
| `esc()` | `& < > "` を実体参照にする |

`Folio.text()` の中身は **Qt のリッチテキスト**。
`.qet` では XML 属性の中に入るので、生の `"` を混ぜると図面が壊れる。`esc()` を通すこと。

文字の大きさは モジュール先頭の定数で決まる。

| 定数 | 既定 | 何の大きさか |
|---|---|---|
| `LBL_PT` | 14 | 部品ラベル（機器記号）のポイント数 |
| `LBL_X` `LBL_Y` | 10, -16 | 部品ラベルの位置（部品の原点から） |
| `NUM_PT` | 11 | 導体の線番のポイント数 |

## check_qet.py — .qet を検証する

```bash
py -3 tools/check_qet.py 出力.qet
```

### 部品定義は .qet の中から採る

`qetgen.save()` が定義を `.qet` に埋め込むので、**まず埋め込みを見る。**
これで検証は `.qet` 1ファイルで完結し、記号がディスクのどこにあるかに依存しない。
**`.elmt` が手元に無い PC でも、生成した `.qet` をそのまま検証できる。**

埋め込みに無いものだけ `paths.py` の探索先から探す。出力の
`部品定義: 埋め込み 3 種 / ディスク 1 種` がその内訳。

### 見る項目

| 項目 | 判定 |
|---|---|
| 部品定義の欠落 | 埋め込みにもディスクにも無い |
| 図枠からのはみ出し | 部品の外形が `cols×colsize` × `rows×rowsize` の外に出ている |
| 部品どうしの重なり | 外形が**両軸とも2単位を超えて**重なっている |
| 導体の端子未指定 | `element1` / `terminal1` / `element2` / `terminal2` のどれかが欠けた導体＝つながっていない線 |
| 相互参照の数 | `link_uuid` の総数。コイルと接点の紐づけが期待どおりか |

併せて **線番の一覧** と **JIS 図記号番号** を出す。

**定義が見つからない部品は、重なり・はみ出しを一切検証できない。**
それを「問題なし」と誤読しないよう、その旨と図面上の個数を明示して要確認に数える。

```
部品定義: 埋め込み 0 種 / ディスク 0 種
  ✖ 定義が見つからない 1 種（この部品は重なり・はみ出しを検証できていない）
      30_a接点.elmt  図面上 3 個
    探した場所: ...\elements / ...\QElectroTech\elements
```

### 終了コード

| | |
|---|---|
| `0` | 問題なし |
| `1` | 要確認あり |
| `2` | 引数が無い・ファイルが無い |

### informations の書式が決まっている

JIS 図記号番号の抽出は、**次の文字列の完全一致**で拾っている
（[check_qet.py:135](../tools/check_qet.py#L135)）。

```
JIS C 0617 / IEC 60617 07-02-01
```

`.elmt` の `<informations>` はこの書式で書くこと。
表記がずれると番号が拾われず、採録状況の突き合わせができなくなる。
**記号を描き始める前にすでに決まっている記法。**

## 直したもの

以前あった落とし穴。もう無いが、古い図面や覚え書きに出てきたときのために残す。

| 症状 | いま |
|---|---|
| `<circle>` が黙って描かれなかった | `ellipse` に正規化して描く |
| `<line>` の端末装飾（矢印・丸・菱形）が無視された | 4種とも描く |

| `<dynamic_text>`（ラベル欄）が描かれなかった | 青で位置を示す |
| PNG のキャプションで日本語が豆腐（□）になった | 日本語フォントを先に試す |
| `Part.term('n')` が同じ向きの端子で黙って先頭を返した | 曖昧ならエラーにする |
| `check_qet.py` が `.qet` の埋め込み定義を見なかった | 埋め込みを先に見る |
| ツールが `カスタム部品/` などの固定フォルダを見ていた | `paths.py` に集約 |

## XML そのものについて

**`.elmt` と `.qet` の構造は [QETのXML.md](QETのXML.md) に移した。**
公式仕様書とのちがい、文字の座標の意味、フォリオ参照や相互参照の仕組み、
表示が壊れる条件はそちら。ここは**ツールの使い方**に絞る。

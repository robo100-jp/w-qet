# 寸法基準

記号どうしを並べたときに端子位置が揃わないと導体が引けない。**先に決めておく必要がある。**
作業計画の「決まっていないこと #2」に対する答え。

## 根拠

3つを突き合わせて決めた。

| 出どころ | 効力 |
|---|---|
| [QET 公式 doc/elements_guidelines](https://qelectrotech.org/wiki_new/doc/elements_guidelines) | 記号作成の規則。**WTFPL** なので従うことに制約は無い |
| QET 同梱コレクション 8597個の**寸法・属性の統計** | 実装が実際に何を要求するか。図版は見ていない |
| 手元のユーザーコレクション 33個 | **既存の図面との互換**。ここを崩すと過去の図面と混ぜられない |

> 公式の XML 仕様ページは最新でも「≥0.3」世代で、**0.100.0 とはかなり離れている**。
> 仕様書だけを信じず、実物の統計と照らして決めた。差分は [ツール.md](ツール.md) に記録。

## 決めたこと

### グリッド

**10。これは規格の作図モジュール M と一致する**（実測で確認。後述）。

**端子の座標と外形寸法はグリッドに載せる。** `width` と `height` は10の倍数
（同梱8597個すべてが満たしていて、実装側の要求と見てよい）。

**ただし 10×10 は使わない。20×20 以上にする。** QET がプレビュー画像を作れず、
部品パネルで名前がファイル名に化ける。ログに次が出るので分かる。

```
QPainter::begin: Paint device returned engine == 0, type: 2
```

同梱8597個でも 10×10 は4個しかない外れ値の寸法。**短辺が10でも長辺があれば通る**
（30×10 などは同梱に200個ある）。`check_elmt.py` が弾く。

**記号内部の頂点はグリッドに載せなくてよい。** 規格自身が載せていない。
07-02-03（b接点）の可動片の先端は (1.76M, 2.79M) で格子点上にない。
**形は規格に従い、無理に丸めない。**

### 端子の間隔

| 種別 | 端子間 | 端子の座標 |
|---|---|---|
| **標準の機器**（接点・コイル・表示灯・押しボタン等） | **60** | `y = -30` と `y = +30` |
| **大形の機器**（モーター等） | 80 / 100 | `y = ±40` / `±50` |
| **端子・ジャンクション部品** | **30** | `y = -15` と `y = +15` |

横置きの記号は同じ数値を `x` に使う（`x = ±30` など）。

> **なぜ 60 か。** 手元の33個が全部これで、既存の図面がこの間隔で描かれている。
> 同梱コレクションでは 40 が最多（201個）で 60 は2番目（98個）だが、
> **上流に合わせるより手元の図面と揃うほうが実害が少ない。**

### 原点と外形

- **端子は原点に対して対称に置く。** 縦2端子なら `y = ±30`
- `hotspot_x` = `width / 2`（記号を縦軸の上で中央に置く）
- `hotspot_y` = `height / 2`
- `width` / `height` は**記号と端子の広がりを覆う最小の10の倍数**

標準の縦置き2端子なら **`height = 60`、`hotspot_y = 30`**。`width` は記号ごとに決める。

> 手元の33個はここが揃っていない。`30_a接点` は `hotspot_x=10`（幅20の中央）だが
> `31_b接点` は `hotspot_x=0`（左端）で、記号が縦軸の右にぶら下がっている。
> **新しく描くものはこの規則で揃える。**

### 端子の属性

```xml
<terminal x="0" y="-30" orientation="n" name="1" type="Generic"
          uuid="{……}"/>
```

`uuid` `name` `type` は**必須**。0.90 以降の同梱記号は全件が持っている。
公式の XML 仕様ページには載っていない（古いため）。`type` は原則 `Generic`。

**`<terminal>` の並び順を後から変えないこと。** 出現順に id 0,1,2… が振られ、
既に作った `.qet` の導体のつながり先がずれる。足すなら末尾に足す。

### link_type

| 値 | 使う記号 |
|---|---|
| `simple` | 相互参照を持たないもの（表示灯・ブザー・モーター等） |
| `master` | コイル、押しボタンなど**接点を従える側** |
| `slave` | その接点 |
| `terminal` | 端子台・ジャンクション部品 |

日本の慣習でコイルは大文字 `R1`、その接点は小文字 `r1`。
表示の仕組みは [ツール.md](ツール.md) の「接点のラベルは UserText にする」。

### 文字

- **既定の文字サイズは 9**（guidelines）
- **。** Qt が pt を画素に直す比。
  記号の中の文字は同梱コレクションに合わせて **4〜10** に収める
  （同梱23,010個の分布は 2〜9 で、最多は 5・6・4・9）。
  かつて  と誤っていて **QET では1.7倍の大きさになり、
  文字が外形からはみ出していた。** はみ出すと QET が再描画しきれず画面にゴミが残る
- 0.100 の `<text>` は `size="9"` ではなく **`font="Liberation Sans,9,-1,5,50,0,0,0,0,0,Regular"`**
  で持つ。`size` を使っているのは同梱50154個中35個だけの旧形式
- 機器記号（ラベル）は `<dynamic_text>` で置く

### ラベルの位置

**`x = width / 2 + 5`、`y = -height / 2`。** 外形の右上、右端から5だけ離す。

幅の違う記号で見比べて決めた。`x` を固定値にすると幅の広い記号で
**基準点が記号の内側に入る**（幅60・`x=10` で完全に内側）。幅から導く必要がある。
`+5` は外形線と文字が触れないための余裕。

`Halignment="AlignLeft"` `Valignment="AlignTop"` なので、基準点から右下に向かって伸びる。

### 文字は倒れない

**`keep_visual_rotation="true"` を必ず書く。**

```xml
<dynamic_text x="15" y="-30" z="1" text_width="-1"
              Halignment="AlignLeft" Valignment="AlignTop"
              frame="false" rotation="0" keep_visual_rotation="true"
              text_from="ElementInfo"
              uuid="{……}" font="Liberation Sans,9,-1,5,50,0,0,0,0,0,Regular">
    <text></text>
    <info_name>label</info_name>
</dynamic_text>
```

**文字・識別記号は記号を倒しても正立のまま**が正しい（CLAUDE.md の過去の失敗）。
QET のソースで確認した。`true` のとき文字の回転を「基準 − 親の回転」に置いて
親の回転を打ち消す。

```cpp
// dynamicelementtextitem.cpp  parentElementRotationChanged()
this->setRotation(QET::correctAngle(m_visual_rotation_ref - m_parent_element->rotation(), true));
```

属性を**省いたときの既定は `true`**（`.elmt` 側も `.qet` 側も）。
つまり**明示的に `false` と書いたときだけ文字が倒れる。**

> かつて `qetgen.py` が `.qet` に `keep_visual_rotation="false"` を書いていた。
> CLAUDE.md の「横向きにしたときラベルまで倒した」の原因はこれ。現在は `true`。

**実機で確かめた。** `true` / 属性なし / `false` の3通りを並べて置いて回した。

| 書き方 | 回したとき |
|---|---|
| `keep_visual_rotation="true"` | **正立のまま**（いまの全記号がこれ） |
| 属性を書かない | **正立のまま**（既定が `true`） |
| `keep_visual_rotation="false"` | 記号と一緒に倒れる |

### 記号の中の文字は一緒に倒れる。それでよい

**`<dynamic_text>`（ラベル欄）と `<text>`（図形の一部）は別物。**
`keep_visual_rotation` は `<dynamic_text>` にしか効かない。

`Θ`（温度）`V`（電圧計）`Fe`（鉄）`I >`（過電流）のように**記号の中に描いた文字は
`<text>` なので、記号を回せば線や円と同じように倒れる。**
37個がこれに当たる。

**倒れたままでよいと決めた。**

- QET の同梱コレクションも **94% が静的な `<text>`** で同じ挙動。上流と揃う
- `<dynamic_text>` に置き換えれば正立にできるが、**図面上で文字が個別に選択・移動・
  編集できてしまう。** 07-12-06 のように11個の文字を持つ記号は扱いにくくなる
- そもそも同梱の `UserText` は `keep_visual_rotation="false"` が最多（1万1千個）で、
  上流はむしろ積極的に一緒に倒している

> 後から「文字が倒れている」と見えても直さないこと。**決めてある。**
> 倒したくない記号が出てきたら、その記号だけ `<dynamic_text>` にする。

### 線

- 既定は `line-weight:normal`。補助的な線だけ `thin`
- `line-style` は `normal` / `dashed` を基本にする。`dotted` `dashdotted` も実装は解釈するが使わない
- 色は付けない（`color:black`）。表示灯など色が意味を持つものだけ例外
- **アンチエイリアスは有効。ただし水平・垂直・45°の線だけ `antialias="false"`**（guidelines）
- 丸は `<ellipse>` で描く。`<circle>` も同義だが1つに寄せる

### informations

図記号番号は次の書式ちょうどで書く。`check_qet.py` がこの文字列の完全一致で拾う。

```
JIS C 0617 / IEC 60617 07-02-01
```

**「JIS準拠」とは書かない。**「JIS C 0617 を参考に作成」とする（CLAUDE.md）。

### 名前とファイル名

- **ファイル名もフォルダ名も ASCII にする。日本語を入れない。**

  | | QET でどうなるか |
  |---|---|
  | ファイル名に日本語 | **記号名が `<name lang="ja">` ではなくファイル名（拡張子つき）に化ける** |
  | フォルダ名に日本語 | **`qet_directory` が読めず、部品パネルでフォルダ名が空欄になる** |

  ASCII名と日本語名を同じ深さ・同じ親に並べて実機で確かめた。
  同梱コレクションが `10_electric` `20_logic` と全部ASCII名なのもこのためだろう。
  `check_elmt.py` が `elements/` 以下のパスに非ASCIIが混じったら弾く。

- ファイル名は **`図記号番号.elmt`**（例 `07-02-01.elmt`）。
  161個を扱うので、図記号番号だけで一意・整列可能。
  規格に無い部品は内容を表す英字（例 `junction_tee.elmt`）
- **日本語名は `.elmt` の中の `<name lang="ja">` が持つ。**
  部品パネルにはそちらが出るので、**ASCIIファイル名にしたほうがむしろ読みやすい**
  （ファイル名が出てしまう状態より）。`docs/採録状況.md` が番号と和名の対応表になる
- **出所で分け、さらに節ごとに分ける。**

  ```
  elements/
    JIS_C_0617/          規格を参照して描き起こしたもの
      07-02/             ← ASCII名。表示名は qet_directory が「07-02 接点」と持つ
        07-02-01.elmt
        qet_directory
    drawing_aids/        規格に無い、作図の都合のもの（端子・ジャンクション）
  ```

  **規格に基づくものと、そうでないものを混ぜない。**
  出所を後から追えなくなると、「JIS C 0617 を参考に作成」と言えるのが
  どれなのか分からなくなる。
- 各フォルダに `qet_directory` を置くと QET の部品パネルに日本語名で出る
- `<name lang="ja">` を主とし、`<name lang="en">` も併記する
- 公式 guidelines はファイル名をフランス語小文字 `^[a-z_]+$` と定めている。
  **かつては「日本語名で引けるほうが実務で効く」として採らなかったが、撤回した。**
  日本語ファイル名では QET が記号名を読めない（上表）。実機で確かめた結果。
  番号で引くぶんには `paths.py` の前方一致が効くので不便はない
  （`py -3 tools/render_elmt.py 07-02-01`）

## 標準の骨格

縦置き・2端子・標準寸法の記号は、この形から始める。

```xml
<?xml version="1.0" encoding="UTF-8"?>
<definition width="20" height="60" hotspot_x="10" hotspot_y="30"
            type="element" link_type="slave" version="0.100.0">
    <uuid uuid="{……}"/>
    <names>
        <name lang="ja">a接点</name>
        <name lang="en">Make contact</name>
    </names>
    <informations>JIS C 0617 / IEC 60617 07-02-01</informations>
    <description>
        <!-- 図形。原点対称に -->
        <dynamic_text x="15" y="-30" z="1" text_width="-1"
                      Halignment="AlignLeft" Valignment="AlignTop"
                      frame="false" rotation="0" keep_visual_rotation="true"
                      text_from="ElementInfo" uuid="{……}"
                      font="Liberation Sans,9,-1,5,50,0,0,0,0,0,Regular">
            <text></text>
            <info_name>label</info_name>
        </dynamic_text>
        <terminal x="0" y="-30" orientation="n" name="1" type="Generic" uuid="{……}"/>
        <terminal x="0" y="30"  orientation="s" name="2" type="Generic" uuid="{……}"/>
    </description>
</definition>
```

`x="15"` は `width/2 + 5` = `20/2 + 5`。

描いたら**必ず**画像にして目視する。座標を読むだけでは形の誤りに気づけない。

```bash
py -3 tools/render_elmt.py 07-02-01
```

## 規格と突き合わせた結果

第7部 2024年版を実測して確認した。**寸法基準は変更不要だった。**

### 1M = 10 だった

07-02-01（a接点）の図を、規格が図に添えているドット格子ごと画素で測った。
格子間隔は均一（M = 120.77 px @600dpi）で、記号は縦 **6M**。
端子間 60 と突き合わせると **1M = 10**、つまり**このプロジェクトのグリッドが
規格の作図モジュールそのもの**だった。

| 実測（07-02-01） | M 単位 | 本プロジェクト |
|---|---|---|
| 上リード | x=2M, y=1M→3M | (0,-30)→(0,-10) |
| 可動片 | (1M,3M)→(2M,5M) | (-10,-10)→(0,10) |
| 下リード | x=2M, y=5M→7M | (0,10)→(0,30) |
| **端子間** | **6M** | **60** |

根拠の違う2つ——**手元の既存記号との互換**と**規格の作図モジュール**——が
一致したので、端子間 60 はこのまま使う。

### 記号の向きは規格どおりにする

**a接点は可動片が左へ、b接点は横棒と可動片が右へ出る。** 規格の図がそうなっている。

端子はどちらも軸上（x=0）なので**配線は揃う**。違うのは見た目の重心だけ。
ラダーに並べたときの見え方を揃えるため b接点を左右反転する案もあったが、
**規格どおりを採る。**「JIS C 0617 を参考に作成」と言い切れる状態を保つため。

> 後から「揃っていない」と見えても直さないこと。**規格がそうなっている。**

### 規格票の図は縦横で縮尺が違う

規格票の図は表のセルに入れられていて、**縦横が同じ比で拡縮されていない。**
ページによって横 113.25px／縦 120.44px のように 6% ずれる。

1つの M で測ると座標が格子に乗らず、原因の分からない半端な数値になる。
**横は列の間隔、縦は行の間隔で別々に測る。** `measure_page.py` はそうしてある。
縦横の差が 1% を超えると警告を出す。

ページによってはドットの検出に失敗する（行や列が抜ける）。
数値が整数に乗らないときは格子の検出を疑い、ドットの座標を直接見ること。

### 可動接片の角度は2種類に統一する

| | 可動接片 | 備考 |
|---|---|---|
| メーク接点系 | `(-11,-12) → (0,10)` | 傾き 1:2 |
| ブレーク接点系 | `(7.5,-12.5) → (0,10)` | 傾き 1:3 |
| 切換え接点 | `(-14.5,-12.5) → (0,10)` | 固定接点が 2M 離れるぶん寝る |

切換え接点（07-02-04 とその応用）では、**固定接点側の横棒は 1M いっぱい**
（`(-20,-10) → (-10,-10)`）まで伸ばし、可動接片はその上を横切らせる。
横棒の途中から生やすと接点が閉じて見えない。

規格票はページごとに 0.5〜1 ほど揺れている。矢羽根や直交線を避けるために
少し伸ばしてあるページもある。**が、同じ基本図記号が図面上に並んだとき
角度が違って見えるのは実用上まずい**ので、この2つに揃える。

> 07-02-01（a接点）と 07-02-03（b接点）だけは規格票の値どおりで、
> 可動片が短い（`(-10,-10)`／`(7.5,-12)`）。基本形なので変えていない。

### 何度も出てくる限定図記号

| 図記号 | 描き方 |
|---|---|
| 限時（落下傘） | 半径 8.5 の半円と、y=±1.5 の平行2本のロッド。**ロッドは必ずカップの膨らんだ側に付く**。開いた向きでどちらの動きが遅れるかを表す |
| 機械的連結 | 破線。線種は `line-style:dashed` |
| 確実動作 | 半径 10 の円の中に右向きの矢 |
| リミットスイッチの操作子 | 三角。底辺は可動接片の上に載り、頂点は接片から離れる側を向く |
| 温度 | 斜体の `Θ`。`elmtgen.text()` で置く |
| 自己動作（バイメタル） | 角ばった山形。左端から可動接片まで一続きに引く |

### 規格票にリード線が無い図記号

07-12（複合スイッチ）のように、箱だけで外に線が出ていない図記号がある。
そのままでは導体がつながらないので、**外形の縁に端子を足す**。
足したことは `<informations>` に必ず書く。
